# Параметры конфигурации

Конфигурация влияет на поведение OneScript. Каждый конфигурационный параметр считывается при старте процесса и действует на протяжении всего срока работы процесса.
Конфигурационные параметры указываются в формате `ключ=значение`.

| Параметр | Описание |
|---|---|
|lib.system|Путь к системному каталогу библиотек. В этом каталоге загрузчик библиотек ищет библиотеки.|
|lib.additional|Дополнительные каталоги библиотек, которые можно указать через точку-с-запятой|
|encoding.script|Название кодировки, в которой по умолчанию считываются файлы скриптов. Если в файле есть метка BOM, то используется она.|
|systemLanguage|en или ru. Язык в котором выдаются сообщения системы.|
|runtime.default|native или stack. Определяет [исполняющую среду](/learn/native) по умолчанию.|

## Расположение конфигурации

Параметры конфигурации могут располагаться или в файлах `oscript.cfg` или в переменной окружения `OSCRIPT_CONFIG`. Действуют сразу все параметры, т.е. финальный эффективный конфиг складывается объединением всех найденных параметров конфигурации.

При этом, если несколько расположений определили один и тот же параметр, то действует последний (он затирает собой предыдущее значение).

### Приоритет применения конфигураций

* Сначала считывается системный файл oscript.cfg который находится рядом с исполняемым файлом движка `oscript.exe`
* Затем, считывается файл oscript.cfg, который находится рядом со скриптом, который был запущен. Если положить рядом со скриптом файл oscript.cfg, то значения в нем перезапишут значения системной настройки.
* Переменная окружения `OSCRIPT_CONFIG`. Параметры из переменной окружения перезапишут все предыдущие.

## Конфигурационные файлы

Конфигурационный файл имеет синтаксис ключ=значение, причем отдельные строки могут быть закомментированы с помощью символа `#`.

```ini
#Конфигурационный файл OneScript

# Корневой каталог системных библиотек
lib.system = C:\Users\ovsia\AppData\Local\ovm\current\lib

#Дополнительные каталоги поиска библиотек
#lib.additional = C:\somedir;C:somedir2;

# Настройки кодировок.
# Можно указывать стандартное имя кодировки, либо значение default для выбора системной кодировки

#encoding.script=utf-8

#systemlanguage = ru
```

## Переменные окружения

Параметры конфигурации могут быть указаны в переменной окружения OSCRIPT_CONFIG, где они разделяются точкой-с-запятой.

```cmd
set OSCRIPT_CONFIG=systemLanguage=ru
```

Здесь мы переопределяем параметр конфигурации systemLanguage на русский.

## Поиск библиотек {#library-search}

Когда в скрипте встречается директива `#Использовать` без кавычек (например, `#Использовать json`), движок выполняет поиск указанной библиотеки по нескольким каталогам в определенном порядке. Первый найденный каталог с именем библиотеки используется для загрузки.

### Порядок поиска библиотек

1. **Каталог `oscript_modules`** рядом со скриптом — локальные зависимости проекта
2. **Каталоги из `lib.additional`** — дополнительные каталоги, указанные в конфигурации
3. **Каталог `lib.system`** — системный каталог библиотек (глобальная установка)

Поиск выполняется последовательно: как только библиотека найдена в одном из каталогов, поиск прекращается. Это позволяет «перекрывать» глобальные библиотеки локальными версиями.

::: tip Обратите внимание
Если имя библиотеки указано **в кавычках** (например, `#Использовать "lib/mylib"`), то путь трактуется как файловый путь относительно каталога текущего скрипта, и описанный выше механизм поиска не применяется.
:::

### Каталог oscript_modules

Каталог `oscript_modules` является аналогом локальных зависимостей проекта (подобно `node_modules` в экосистеме Node.js). Он размещается рядом с запускаемым скриптом и содержит подкаталоги с библиотеками, необходимыми именно этому проекту.

```
my-project/
├── src/
│   └── main.os              ← запускаемый скрипт
├── oscript_modules/
│   ├── json/                ← локальная копия библиотеки json
│   └── fs/                  ← локальная копия библиотеки fs
└── packagedef
```

При установке зависимостей через пакетный менеджер `opm` с флагом локальной установки, пакеты размещаются именно в `oscript_modules`. Это позволяет каждому проекту иметь свой набор библиотек нужных версий, независимо от глобально установленных.

### Параметр lib.additional

Параметр `lib.additional` позволяет указать один или несколько дополнительных каталогов для поиска библиотек. Каталоги указываются через точку-с-запятой.

```ini
lib.additional = /opt/my-libs;/home/user/shared-libs
```

Этот параметр удобен, когда необходимо:

* Использовать общие библиотеки, расположенные вне стандартного системного каталога
* Подключать библиотеки из нескольких источников одновременно
* Организовать разные наборы библиотек для разных целей

### Примеры настройки

#### Локальная установка пакетов

При работе над проектом рекомендуется устанавливать зависимости локально. Для этого в каталоге проекта выполните:

```sh
opm install -l
```

Пакеты будут установлены в каталог `oscript_modules` рядом с `packagedef`. Теперь при запуске скрипта из этого проекта библиотеки будут найдены в первую очередь в `oscript_modules`, а не в системном каталоге.

#### Нестандартное расположение движка

Если OneScript установлен в нестандартный каталог (например, `/opt/oscript`), системный `oscript.cfg` рядом с `oscript.exe` будет содержать путь `lib.system`, указывающий на каталог `lib` внутри этого каталога. Если нужно использовать дополнительные библиотеки из другого расположения, укажите их в `lib.additional`:

```ini
lib.system = /opt/oscript/lib
lib.additional = /home/user/my-libs
```

#### Переопределение через переменную окружения

Если необходимо временно изменить каталог поиска библиотек без редактирования файлов конфигурации, используйте переменную `OSCRIPT_CONFIG`:

```sh
export OSCRIPT_CONFIG="lib.additional=/tmp/test-libs"
oscript my-script.os
```

#### Использование нескольких проектов с разными зависимостями

Каждый проект может содержать собственный `oscript.cfg` и каталог `oscript_modules`, что позволяет изолировать зависимости:

```
project-a/
├── src/
│   └── app.os
├── oscript_modules/
│   └── json/         ← версия 1.2.0
├── oscript.cfg
└── packagedef

project-b/
├── src/
│   └── app.os
├── oscript_modules/
│   └── json/         ← версия 2.0.0
├── oscript.cfg
└── packagedef
```

В этом случае каждый проект будет использовать свою версию библиотеки `json`, при этом глобальная установка никак не повлияет на работу проектов.

### Итоговый приоритет поиска

Механизм поиска библиотек тесно связан с [приоритетом конфигурации](#приоритет-применения-конфигураций). Финальный набор каталогов для поиска формируется следующим образом:

1. `oscript_modules` — каталог рядом со скриптом (наивысший приоритет)
2. `lib.additional` — каталоги, полученные из эффективной конфигурации (с учетом приоритетов конфигов)
3. `lib.system` — системный каталог из эффективной конфигурации (наименьший приоритет)

Таким образом, локальные зависимости всегда имеют приоритет перед глобальными, что позволяет безопасно экспериментировать с версиями библиотек на уровне проекта.
